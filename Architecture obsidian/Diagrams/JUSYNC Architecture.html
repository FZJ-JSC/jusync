🔐 Hash Tracking Lifecycle — Per Mesh File

How a single file moves through states from first spawn to final destruction.

stateDiagram-v2
    [*] --> Unknown: File never seen in UE
    Unknown --> HashStored: Initial spawn → write FileHashLo/Hi[filename]
    HashStored --> Unchanged: V2 notification: hash match → SKIP refresh
    HashStored --> Changed:   V2 notification: hash mismatch → refresh
    Unchanged --> HashStored: Next notification, re-evaluate
    Changed --> Downloading: REQ_GET_FILE → 4MB chunks → accumulate
    Downloading --> Parsing: Full file → UsdProcessor::ExtractMeshData
    Parsing --> Spawning: FJUSYNCMeshData → SpawnRealtimeMeshAtLocation
    Spawning --> Verifying: New actor spawned, old still visible
FileToActorMap swap
    Verifying --> HashUpdated: Write new FileHashLo/Hi, update generation
    HashUpdated --> HashStored: Old actors destroyed, full cycle done
    HashUpdated --> [*]: PIE stop / actor cleanup
